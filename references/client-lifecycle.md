# 客户端流量重置与自动续期

本流程使用 3x-ui v3.9.0 的面板原生功能。只维护用户指定的客户端；不重新安装面板，不创建 VPS 重置脚本、cron 或定时任务 API Token。

## 先确认用途和对象

确认客户端 email、每周期配额、重置日、面板时区，以及是否需要到期限制。区分：

| 用户用途 | 到期时间 | 独立流量重置 | 自动续期 |
| --- | --- | --- | --- |
| 长期给同事使用，每月指定日恢复额度 | 留空 / 0 | 每月，指定日期 | 不续期 |
| 有截止日期，到期后自动进入下个收费/使用周期 | 首次截止时间必须设置 | 通常关闭 | 固定天数 / 日历周 / 日历月 |

每月 17 日、50 GB 只是示例，不是所有新 VPS 的默认值。默认 `admin` 继续无限流量、长期有效；给同事用时选择其独立客户端，不要把 admin 或整个入站改成 50 GB。已有共享客户端的配额会按该身份统计，不是给每个节点分别发一份额度。

用户只问“怎么配置”时，解释填写方法即可。用户要求代为配置时，先读取当前客户端、关联入站及面板时区，备份数据库，再进行限定修改。保留 UUID、subId、auth、密码、IP/HWID 限制、关联关系和每个入站的 flow；不要顺便清零现有使用量或重新启用手动禁用的账号。

## 长期有效，每月 17 日重置 50 GB

在“客户端 → 目标用户 → 编辑 → 基本”中填写：

| 面板项目 | 示例值 |
| --- | --- |
| 流量上限（GB） | 50 |
| 过期时间 | 留空（长期有效） |
| 首次使用后开始 | 关闭 |
| 流量重置 | 每月 |
| 每月重置日 | 17 |
| 自动续期模式 | 不续期 |

保存后重新打开目标客户端确认生效。这表示每月 17 日按面板时区执行流量周期重置，不是每隔 30 天，也不是每次更新订阅就清零。额度提前用完会暂停使用，下一次计划重置后可恢复；手动禁用不应当作额度耗尽自动解除。

API 中对应的业务字段片段如下，**不是可以直接发送的完整更新请求**：

```json
{
  "totalGB": 53687091200,
  "expiryTime": 0,
  "trafficReset": "monthly",
  "trafficResetDay": 17,
  "reset": 0,
  "resetDay": 0,
  "resetWeekday": 0,
  "resetMax": 0
}
```

`totalGB` 虽然名为 GB，API 实际传字节：面板 50 GB 对应 `50 × 1024³`，不能直接传 `50`。`expiryTime` 是 Unix **毫秒**；0 表示无期限，负数表示首次使用后计时，不能把秒时间戳或负值当成长期有效。

## 按到期时间自动续期

只有用户需要“每个周期都有到期边界，再自动延长”时才用本方案。例如每月 17 日续期：

- 自动续期模式选“日历月”，按日期续期填 17。
- 设置首次过期时间为下一个预期的 **17 日 00:00:00（面板时区）**，或使用表单的首次日历截止时间按钮。仅选择模式、过期时间仍为空，不会启动续期。
- 最大续期次数填 0 表示不限制次数；正数表示最多消耗的续期周期数，包括服务离线后的补续，不是任务执行次数。
- 首次使用后开始默认关闭；用户明确要激活后计时才启用，并核对预览。
- 自动续期本身会清零该客户端流量。独立“流量重置”通常选“不重置 / never”，不要为了同一个月度周期重复配置两套计划。

`17 日 00:00:00` 是截止边界，表示前一天最后一秒仍有效；不要填 `17 日 23:59:59` 再声称整天有效。日历月按真实月份推进，31 日在短月取月末；固定 30 天会逐渐偏离每月固定日。

| 续期模式 | API 字段 |
| --- | --- |
| 不续期 | `reset=0, resetDay=0, resetWeekday=0` |
| 固定间隔 N 天 | `reset=N, resetDay=0, resetWeekday=0` |
| 日历月，指定日 D | `reset=0, resetDay=D, resetWeekday=0` |
| 日历周，周一到周日 | `reset=0, resetDay=0, resetWeekday=1..7` |

`resetDay` 是**到期续期日**，`trafficResetDay` 才是**独立流量重置日**；不要互相替代。v3.9.0 新增的是日历周模式，不是本次才有每月重置。每周续期要求主面板与参与节点都支持 `resetWeekday`；混合旧版本或降级前先备份并转换模式，避免旧版忽略该字段或误清理耗尽客户端。

## 时区与原生计划

- 核对面板设置中的时区以及实际预览；不能仅凭本机浏览器时间或 VPS 的 `date` 判断计划边界。中文用户需要北京时间时，确认面板为 `Asia/Shanghai`。
- 不要为一个客户端修改整个面板时区：时区影响所有原生计划，先确认其他用户安排。
- 不执行手动“重置流量”来验证日期；该按钮会立即清零，不会证明未来计划能按时执行。
- 若面板停机/节点离线，不能保证在零点立即处理；回读计划和节点同步状态即可，不承诺无服务条件下也准时恢复。

## v3.9.0 API 与保存规则

端点均位于实际面板 web base path 之下，使用已有 Bearer Token，不把 Token 放入 URL 或日志。以当前运行版本的 OpenAPI 为准：

- `GET /panel/api/clients/get/{email}`：读取一个客户端、关联入站和使用量。
- `POST /panel/api/clients/update/{email}`：更新目标客户端，并传播到关联入站。
- `POST /panel/api/clients/renewalPreview`：只读预览续期日期，不保存、不清零；请求包含 `expiryTime/reset/resetDay/resetWeekday/resetMax/resetCount`。
- `POST /panel/api/inbounds/setEnable/{id}`：只切换入站启用状态；不是客户端启用接口。

**客户端 update 是替换完整业务字段，不是 PATCH。** 先读取完整现值，转换为该接口的 `Client` 请求形状，保留不相关字段，再合入目标字段。v3.9.0 的 get 返回 `obj.client` 为 `ClientRecord`：其数字 `id` 是数据库 ID，字符串 `uuid` 才是 VLESS 身份；update 的字符串 `id` 则对应这个 UUID。不可原样转发整个 GET 响应、数字 ID 或上面的字段片段。其他协议字段也须按 schema 转换，保留 `limitHwid`、密钥及逐入站 flow 覆盖。

不要用 `/panel/api/inbounds/update/{id}` 或入站 JSON 编辑器改已有客户端的配额、到期、启用状态、续期模式；v3.9.0 为避免旧表单覆盖实时续期和统计，保存入站会保留这些客户端状态。也不要仅改 `inbounds.settings` 就声称生命周期已更新。

HTTP 200 不等于保存成功：检查响应 `success`、错误消息和节点待同步状态；`success:false` 可能已有部分关联入站应用变更，先回读再决定补救，不能盲目反复提交。新建/关联用户同样使用客户端专用接口；不要批量更新全部用户。

## 保存后只读验收

1. 重新读取目标客户端，核对额度（字节）、`expiryTime`、`trafficReset`、`trafficResetDay`、`reset/resetDay/resetWeekday/resetMax`，以及手动启用状态未被意外改变。
2. 核对 UUID、subId、关联入站、逐入站 flow、IP/HWID 限制未改变；只报告一致/不一致，不输出秘密值。
3. 到期续期模式用原生预览确认首次截止、下一周期日期、时区和次数；长期无期限模式确认 `expiryTime=0`、自动续期关闭。
4. 核对父入站没有更早的到期或更小的总流量上限，避免客户端仍长期有效却被入站限制截断。
5. 多节点部署核对变更传播与待处理重置；不要强行重置现有流量来测试。最终说明这是“设置已保存并回读”，不冒充“未来重置已实测”。

只输出指定账号的业务摘要，例如“长期有效，每月 17 日按 Asia/Shanghai 重置 50 GB；不启用到期续期；保存并回读通过”。
